# eclass-board

Статическая страница для GitHub Pages: актуальные домашки, расписание и статистика по предметам (оценки, посещаемость, пропущенные задания) из [eClass IUT](https://eclass.inha.ac.kr/).

## Как это работает

GitHub Pages — статика, а eClass требует логина, поэтому данные собирает GitHub Actions:

1. `scraper/fetch.py` раз в 2 часа логинится в eClass и читает список курсов, страницы заданий и квизов, силлабусы (расписание), отчёт по оценкам, посещаемость и календарь.
2. Результат пишется в `site/data.json` — файл не коммитится, а уезжает прямо в деплой Pages. С секретом `DATA_PASSPHRASE` файл шифруется целиком (AES-256-GCM, ключ из пароля через PBKDF2-SHA256, 600 000 итераций); без него оценки и посещаемость не публикуются вообще.
3. `site/` — страница без сборки и зависимостей: расшифровывает JSON прямо в браузере (WebCrypto) и рисует вкладки «Домашки», «Расписание» и «Статистика».

Если eClass недоступен или логин не прошёл, job падает, а на Pages остаётся прошлая версия; внизу страницы видно время последнего обновления.

## Настройка

1. Создай **публичный** репозиторий и запушь туда этот проект (ветка `main`).
2. Settings → Pages → Source: **GitHub Actions**.
3. Settings → Secrets and variables → Actions → New repository secret:
   - `ECLASS_USERNAME` — ID в eClass;
   - `ECLASS_PASSWORD` — пароль;
   - `DATA_PASSPHRASE` — пароль для данных сайта, не короче 12 символов. Лучше случайный, сохранённый в менеджере паролей:

     ```bash
     python -c "import secrets; print(secrets.token_urlsafe(18))"
     ```
   Шаги 1–3 можно сделать и из терминала — после `pip install pynacl`:

   ```bash
   python tools/setup_github.py
   ```

   Скрипт работает через вход в GitHub, который git сохранил для `git push`. Перед каждым изменением на GitHub он спрашивает подтверждение, а ID и пароль от eClass проверяет до того, как сохранить их в секреты. Его же стоит запускать после смены пароля от eClass.
4. Actions → «Update data and deploy» → Run workflow.
5. Открой сайт (адрес — в Settings → Pages) и введи `DATA_PASSPHRASE`. На каждом устройстве это нужно сделать один раз: пароль запоминается в браузере, а кнопка «Забыть пароль» внизу страницы его стирает.

Режим без пароля от eClass: вместо `ECLASS_USERNAME` и `ECLASS_PASSWORD` задай `ECLASS_ICAL_URL` — ссылку «iCal» внизу страницы [календаря](https://eclass.inha.ac.kr/calendar/view.php?view=upcoming). В ней только токен календаря, но в этом режиме нет статуса сдачи, времени дедлайна у заданий, расписания и статистики. Токен меняется вместе с паролем.

## Локальный запуск

```bash
pip install -r requirements.txt
```

```bash
python scraper/fetch.py
```

Без переменных окружения скрипт сам спросит ID и пароль (пароль не отображается и нигде не сохраняется). Локально файл пишется без шифрования — он в `.gitignore` и никуда не уходит; флаг `--public` готовит его так же, как workflow.

```bash
python -m http.server 8137 --directory site
```

Тесты парсеров и шифрования:

```bash
python -m unittest discover -s tests
```

## Что стоит знать

- **Что видно посторонним.** Сайт на Pages открыт всем, у кого есть ссылка, а адрес вида `логин.github.io/репозиторий` легко угадать.
  - С `DATA_PASSPHRASE` без пароля не видно ничего, даже списка курсов.
  - Без него открыто видны курсы, ФИО преподавателей, задания и статусы сдачи, а оценки и посещаемость не публикуются.

  Пароль от eClass в любом случае лежит только в Secrets. Твоё имя в данные не попадает.
- **Пароль данных — случайный.** Зашифрованный файл может скачать кто угодно и перебирать пароли офлайн, поэтому пароль короче 12 символов workflow не примет. Если сменишь `DATA_PASSPHRASE`, сайт попросит ввести новый.
- **Статистика.** «Пропущено» значит: дедлайн прошёл, а в eClass нет ни сдачи, ни оценки. Некоторые преподаватели скрывают отчёт по оценкам — тогда видны только баллы со страниц заданий и квизов, без максимума. Посещаемость — только по курсам, где её ведут в eClass.
- **На iPhone** открой сайт в Safari → «Поделиться» → «На экран „Домой“»: страница будет открываться на весь экран, как приложение, с вкладками внизу.
- **Время пар посчитано.** В силлабусе указаны номера периодов (`Mon 4~6`); период 1 начинается в 08:00, каждый длится 30 минут. Если расписание звонков изменится — поправь `FIRST_PERIOD_START` и `PERIOD_MINUTES` в `scraper/fetch.py`.
- **Чекбоксы хранятся в браузере.** eClass не знает о сдаче через Gradescope и подобные сервисы, поэтому задачу можно отметить вручную — тогда она перестаёт считаться пропущенной и в статистике. Отметка живёт в `localStorage` и не синхронизируется между устройствами.
- **«Актуальные»** — несданные задачи с дедлайном в будущем или просроченные не больше недели назад. Остальное — во вкладке «Все».
- Время везде ташкентское (UTC+5), как показывает eClass.
